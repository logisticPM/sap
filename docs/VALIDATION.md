# Validation and next experiment

## Evidence categories

1. **Implemented behavior:** code, local tests, browser walkthrough and selected stored real-model traces.
2. **Public workflow evidence:** cited desk-study sources, with geography/task limitations.
3. **Synthetic/replay demonstration:** CASE-1042 and all departmental responses; no observed operational outcome.
4. **Unvalidated value:** active labor saved, fewer business errors, earlier arrival, reduced waste, ROI and adoption.

Original v31 validation reported 21 passing workbench tests and completed real runs for initial review, reply review and alternative investigation (12 model requests across those checks). That is engineering evidence on frozen synthetic inputs, not a business impact estimate. This repository's handoff checks are recorded separately in `HANDOFF_CHECKS.txt`.

## Next falsifiable comparison

Use consecutive real additional-supply exception tasks when a partner is available; freeze task selection before examining outcomes. Preserve original timestamps and release information only when it was available. Start with an exploratory 10–20 tasks; do not interpret that sample as powered proof of savings.

Compare **current process**, **strong structured form/rules**, and **Agent-assisted evidence work**. Give all arms the same information, access, task limits and approval policy. The form/rule baseline must include known routing and deterministic checks used by the Agent harness. Record which work is performed by rules versus model. Randomize/counterbalance task assignment to reduce learning effects; freeze rubric and budgets before scoring.

Primary safety measures: unsupported commitments, wrong quantities/units, missed conditions, stale evidence, unauthorized disclosure, duplicate clarification and wrong next action. Independent reviewers use source-linked answer keys and adjudicate disagreements. Measure actual active human work separately for planner and supplier; record elapsed waiting, production and transport separately. Event gaps are not labor time. Do not estimate a percentage saving without participant measurements.

Proceed only if critical errors do not worsen and total human burden improves enough to cover model, verification, onboarding and integration costs. If forms/rules perform as well, prefer them. If production/transport dominates or suppliers will not participate, reconsider the product wedge.

## GitHub handoff limits

Public replay is single-browser state with no authentication. Test data is synthetic and inspectable. Model outputs are retained evidence, not independently verified truth. The portable backend is not a deployment security audit and was not connected to a real SAP tenant or supplier system.
